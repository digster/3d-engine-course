12. The golden, and why it is blind to this lesson

The reference render is byte-identical, as it has been for every lesson since 5.1. Run it anyway — “I am confident it cannot have changed” is what a test is for — but be clear that it is a null instrument here, and say so structurally rather than hopefully:

  • demo::write_reference_shot renders through soft_renderer.cpp, raster.cpp and framebuffer.cpp, driven by demos/common/demo_scene.cpp.
  • renderable.cpp is a new translation unit that nothing in that list calls. It reads a registry, and the reference scene has no registry.
  • engine.hpp gained fifteen #include lines and no declarations, and nothing under demos/common includes it — §3 established that nothing anywhere did.
  • The CMake lint emits a message and never a compile flag.

So the picture cannot move, and a byte-identical result is evidence of nothing except that nobody edited a file they did not mean to. That is worth ninety seconds and no more. The real instrument for this lesson is verify_512 §B — the matrix round trip every object drawn through collect_renderables depends on — and it carries a control that fires at 1.0.

A second shot now exists

collector --shot is itself a characterization test, and a better one than the golden for anything the ECS touches: it runs 240 deterministic simulation steps and prints four numbers derived from them. If a future lesson changes the hierarchy's resolve order, the view's lead-pool choice, or the pool's swap-and-patch, the triangle count will move and this line will say so.

13. Common pitfalls & debugging

Everything is half the size it should be, and some of it is floating

Symptom: the arena is a quarter of its intended area, the pillars stand beside it in the void, and the whole thing reads as a broken camera.
Cause: cube_mesh() spans ±0.5, so a transform's scale is the box's full size. A half-extent passed straight through — the natural thing to do, because a half-extent is what everything else wants — halves every dimension, and using the half-extent as the centre height puts the box half underground.
Fix: one helper that takes a centre and a half-extent and does the doubling (box_at, §7.1). Do not fix the call sites individually; you will miss one.

A debug box is exactly twice the size of the thing it outlines

Symptom: collision proxies look like they have a generous margin.
Cause: debug_lines::box(const mat4&, vec3 half_extent, …) takes the half-extent in the matrix's local space, and the world matrix already carries the scale. Passing metres scales them again.
Fix: pass {0.5f, 0.5f, 0.5f} — the unit cube's own half-extent. The tell is that the error is exactly 2×, never 1.8×: a plausible-looking margin that is exactly a factor of two is never a margin.

A headless run hangs for ever and prints nothing

Symptom: --shot never returns, no output, no crash. CI times out.
Cause: an SDL_assert fired. It expands to a while loop so that RETRY genuinely re-tests, and with no display to put a dialog on and no terminal to prompt at, the default answer keeps arriving and the condition cannot change.
Fix: attach a sampling profiler or debugger and read the top frame — sample <pid> on macOS, gdb -p elsewhere — and the assertion's own function is sitting at the top of the stack. Exercise 5 installs a handler that aborts instead.

Moving objects are subtly harder to interact with than still ones

Symptom: the carousel's orbs feel like they need a bigger pickup radius than the stationary ones.
Cause: something read a world_transform before hierarchy::resolve ran this step, so it saw last step's composition. At 0.45 rad/s and a 4 m radius that is 3 cm — invisible, and far too small to blame on anything.
Fix: one resolve per step, after everything that writes a local transform and before everything that reads a world_transform. If two resolves are genuinely needed, write down why.

An entity exists, looks right in the debugger, and does not draw

Symptom: you spawned it, alive() is true, the component is there, nothing appears.
Cause: it has a renderable and no world_transform. hierarchy::resolve never creates components (5.9, deliberately), so add<renderable> without add_hierarchy_components is silently invisible.
Fix: read renderable_report::unresolved, which exists for exactly this and is on the debug panel for exactly this reason. Before that counter the only symptom was “the orb is not there”.

The first keystroke after clicking into a panel also reaches the game

Symptom: type into the ImGui field and the rover lurches once.
Cause: debug_ui::begin_frame() was called beside the panels in on_overlay rather than first in on_input. The capture flags are computed inside NewFrame, so every read is one frame stale.
Fix: begin_frame() is the first statement of on_input, before gate_.update(...). Lesson 5.11 argued this at length; it is here because a new program is exactly where the ordering gets re-invented.

Your program's log lines never appear, whatever --log spec you pass

Symptom: --log '*=info' shows the engine's messages and none of yours.
Cause: a category past log_category_count is not in name_of's table, so the spec parser cannot address it and it keeps SDL's default floor (§8.6).
Fix: set it in code with SDL_SetLogPriority, or — for anything that is the program's output rather than a diagnostic — use printf and stop calling it a log.

14. Exercises

  1. 1 — A second carousel. Add another pivot at a different radius and a different rate, with the remaining orbs parented to it, and make one of them turn the other way. Then parent the second carousel to the first and predict what the orbs do before you run it.

  2. 2 — A trail with a lifetime. Give the rover a trail: queue one debug line per step from its last position to its current one, with a lifetime of 1.5 s. Then pause the game (add a paused action) and check the trail is still there. Lesson 5.11's expiry rule says it should be; confirm it, and say what would have happened with a subtract-then-test rule and dt == 0.

  3. 3 — Actually interpolate. on_frame takes alpha and throws it away. Keep the previous step's world_transform for every renderable and lerp — position linearly, and the basis by whatever you can justify — then run at a fixed step of 20 Hz and compare. Report the extra memory in bytes per entity.

  4. 4 — const views (open). Make world.view<const renderable>() compile and hand out const renderable&, then change collect_renderables to take a const ecs::registry&. Count how many other functions in this repository could then say what they mean.

  5. 5 — An assertion that does not hang (open). Install an SDL_AssertionHandler that returns SDL_ASSERTION_ABORT when SDL_WasInit(SDL_INIT_VIDEO) is false, and SDL_ASSERTION_ALWAYS_IGNORE never. Decide where it belongs — the engine, or each program — and defend the choice.

Hints

1. set_parent returns a parent_status; read it. A cycle is reported, not crashed, and the second half of this exercise is a good way to see that happen on purpose.

2. The lifetime argument is the last parameter of debug_lines::line and defaults to k_debug_this_frame, which is 0.0. Look at how advance() compares before it subtracts.

3. Interpolating a basis is the hard half and Module 7 is where it is done properly. For this exercise, interpolating position and taking the newer basis is a defensible answer if you say so — and it is what a great many shipped games do for objects that do not rotate quickly.

4. The blocker is that view stores pool<Ts>* and pool<const T> is not instantiable. std::remove_const_t in the storage and the original Ts in each's parameter pack is the shape of the answer.

5. SDL_SetAssertionHandler takes a function pointer and a void*. Note that it must be installed before anything can assert, which is a constraint on where more than on what.

Solution sketches

1. Parenting carousel B to carousel A composes the rotations, so B's orbs sweep an epicycle — the same picture Lesson 5.9's moons drew, arrived at from the other direction. If B turns the other way at the same rate, its orbs travel in a straight line relative to the world, which is a satisfying thing to watch and a genuinely useful sanity check on the composition.

2. It survives, because advance() tests before it subtracts. With subtract-then-test and a strict <, a line whose remaining lifetime is exactly 0 and a dt of 0 never expires — so on a paused clock, a single-frame --shot, or any frame you are stopped in the debugger for, the queue fills and never drains.

3. Two mat4s per entity is 128 bytes, which at this scale is nothing and at a hundred thousand entities is 12.8 MB — precisely the arithmetic Lesson 5.6 measured, arriving in a new place. The usual production answer is to interpolate only what is visible, which needs the culling that Module 6 builds.

4. The change is small and it touches two published headers, which is why this lesson reported it rather than making it. Expect the count in the second half to be larger than you guess: hierarchy_debug_system, every gizmo pass, every serializer, and every query a future editor makes.

5. It belongs in the engine, installed by platform::start, because the property it depends on — “is there a video subsystem” — is the platform layer's business and no program should have to know to ask. The counter-argument worth weighing is that an engine which aborts on your behalf has taken a decision away from you; the answer is that in a headless run there was never a decision to take.

15. Recap & next

The engine now has a game built on it, written from outside the boundary Lesson 5.1 drew, by a program that was not designed to flatter it. That is the capability this lesson adds, and it is a capability of the project rather than the engine: from here on, “does the public API suffice?” is a question with a program attached to it.

Two things in the engine changed. engine.hpp now lists every public header, and a configure-time lint keeps it that way — because §3 established that the file has no consumer, and a header nobody compiles cannot be kept correct by being used. And gfx/renderable.hpp keeps the promise scene.hpp made in Lesson 5.1: Module 5's ECS does now replace the struct with components, the mat4-to- transform conversion lives in exactly one place, and it is exact to the bit rather than nearly so.

Five things did not change, and they are the more valuable half. There is no collision, so a wall is a clamp and a pillar is scenery. There is no text, so the score is drawn by SDL's debug font and vanishes the moment you run headless. There is no audio, so the only rewarding thing in the game is silent. There is no public path from an entity to the GPU renderer, so the engine's real renderer is the one a game cannot reach. And view() has no const overload, so no system in this engine can say that it only reads. Each of those is now named, dated and pointed at the module that owns it — at hour 62 rather than hour 434.

Module 5 is complete. Twelve lessons ago engine was the name of an executable; it is now a library with a public API, an application layer, a logger, handles, an asset store, an ECS, a transform hierarchy, a camera, an input map, a debug drawer, a debug UI — and a game that uses all of them and nothing else.

Which makes the next thing the right next thing. Look again at the arena: the floor is matte because a specular term revealed the triangulation of a 14-metre quad, and the pillars are almost black on the side facing you. Both of those are shading, and Module 6 opens by explaining that the single largest error in every picture this engine has ever produced is not the shading model at all. It is that the numbers have been added up in the wrong space.
