# First item — Lesson 6.2: Radiometry-Lite, and the π that was in the wrong place

**58 of 95 published.** Module 6 is two lessons in.

## The finding, which is the lesson

`shade()` multiplied an albedo by a light and called the product "the light leaving the surface" —
a sentence with no unit in it, which makes "is this energy-conserving?" a question the code cannot
be asked. Putting units on it took four lines of algebra to expose what
`directional_light::intensity` had silently been:

```
albedo · (key · intensity · n·l)  ==  (albedo/π) · E_perp · n·l   ⟹   intensity = E_perp / π
```

**The Lambert BRDF's own π has been living inside the light since Lesson 3.6.** Nothing was
*wrong* — the pictures were fine, the two renderers agreed to a float ULP, twelve goldens matched.
A constant in the wrong place produces correct output right up until a second thing needs it,
which is Lesson 6.4.

## The design, in five decisions

1. **The π goes in the BRDF and the light becomes π** — and the exposure is *derived*, not tuned:
   π is the irradiance under which a white Lambertian renders at exactly 1.0. Named
   `k_reference_irradiance`, documented as a **choice** that 6.10's tonemapper demotes to a default.
2. **Rename, don't re-document.** `intensity` → `irradiance`, because the correct new value is π
   and there is no diagnostic for "same type, new meaning". Default is π too — a default of 1.0
   compiles everywhere and darkens every defaulted scene, which is the failure the rename prevents,
   walked back in through the constructor.
3. **The specular's /π is NOT a normalisation**, and the header says so at length. It puts the two
   lobes on one scale so a single irradiance can multiply both. §6 measures how un-normalised it
   remains.
4. **The energy test lives in the harness, not the engine.** `R(v) = ∫ f_r cos θ dω` is 20 lines of
   `verify_62`, and every later BRDF gets run through it *unchanged* — a test rewritten per BRDF is
   not a test of that BRDF.
5. **`verify_62` needs no GPU.** Its subject is arithmetic, and arithmetic checkable only on a
   machine with a display stops being checked. `verify_48` §F already owns CPU/GPU agreement.

## Traps worth remembering

- **The probe overturned my guess, twice.** I expected the raw Blinn lobe to break energy
  conservation where the engine runs. It does not (0.1386 at shininess 32). The failure that
  survives is that diffuse and specular are **added with no coupling** — 1.1386 for white-on-white.
  That reframes what Fresnel is *for*, and the wrong paragraph was ten minutes from being written.
  **Write a second probe the moment the first disagrees with you.**
- **The ambient term was already exactly right**, and nobody knew why: uniform hemispherical
  radiance through albedo/π integrates to `albedo · L_a` — the π cancels. The one term needing no
  constant is the one nobody put a constant in.
- **`verify_48` §F filled the light uniform from the colour alone**, dropping the scalar. Silently
  correct for four modules because the scalar was 1. Same failure class as 6.1's `_SRGB`-target
  harness bug — two occurrences, so it is a rule now: **a harness that constructs inputs the
  shipped path also constructs will drift, invisibly, while the value is a default.** The ratio
  names it: divide the disagreeing values, get π, look for a missing multiply.
- **An empty diff is evidence only beside a measurement that something changed.** Report both:
  "byte-identical" alone reads as "you changed nothing".
- **Two dead prereq links**, from guessing filenames off lesson *titles*. `check-page.js` does not
  cover links. Twelve lines of Python resolving every href against the filesystem does.
- **Pinned `build_61.py` before touching anything** — first time on time. Six listings, verified

- `check-page.js` caught a label on a shape the eye slides over: at θ = 0 the normal points back up

# Second item — Lesson 6.3: Microfacet Theory

## The lesson in one line

`shininess` is a number that makes the highlight the right size and measures nothing. Replace it
with a **statistical claim about slopes**, and the claim is testable — which is the entire
difference and the source of every finding below.

## The design, in five decisions

1. **The identity is the deliverable**, not the formulas. `∫ D(h) cos θₕ dω = 1`, with the
   backwards reading (projected areas total the flat area) as the reason the cosine is there. Every
   later distribution goes through the same test, unchanged.
2. **Blinn stays in the enum.** Showing `cos^s` satisfies the same identity IS §4's argument, and
   an argument you can run beats one you can read.
3. **Two G forms, because the choice was measurable.** Height-correlated is the default; keeping
   the separable one is only worth the lines because 1.715× makes the default a decision.
4. **The 17× is NOT fixed.** The materials were authored against the wrong constant, so correcting
   it alone blows every highlight out. Exercise 15.1 walks the student into exactly that.
5. **Parts before assembly.** Fresnel is the coupling 1.1386 actually needs; shipping D and G live
   would leave the renderer running a model that is neither the old nor the new one for a lesson,
   and re-baseline the golden twice.

## Traps worth remembering

- **The §A test failed on the first run and the fix was NOT to widen the tolerance.** 1.83e−04 at
  the smoothest roughness. Two runs diagnosed it: refine the grid (no change → not quadrature),
  same formula in `double` (clean → the error is in `float`). The textbook GGX denominator is a
  catastrophic cancellation; `(1−c)(1+c) + α²c²` is identical algebra and **Sterbenz's lemma**
  makes `1.0f - c` exact for c ≥ 0.5. **450× better.** §A now asserts the comparison inline.
- **QUADRATURE ERROR SHRINKS WITH THE GRID; ARITHMETIC ERROR DOES NOT.** Two runs locate any bug
  of this class. Worth having as a reflex.
- **A tolerance widened to admit a failure is a test deleted slowly.** The value of a test with a
  known answer is entirely in believing the known answer.
- **An error a PARAMETER can absorb is invisible.** 17× hid inside `specular::colour` for three
  modules. It only surfaced when 6.2 tried to author against physical values.
- **A figure whose numbers contradict its own caption.** First draft: 32 of 74 facets "aligned",
  i.e. 43% of the surface — the opposite of the model. No geometry check sees this; only reading
  the caption against the drawing does. Tightened to a ~4° cone: 4 of 48.
- **Draw the negative case.** The figure only worked once the *non*-participating facets got faint
  normals. The contrast is the message.
- **An arrow ending in mid-air reads as a drawing error** — and hid a sign bug in the masking
  figure's light direction until the rays were made to terminate on the facet they strike.
- **Plot limits from the data, not from the first curve tried.** A hand-chosen ceiling clipped the
  sharpest NDF flat. The peak is `1/(πα²)`, so it is computable — and the honest picture (peaks
  16× apart, areas all 1) is the better illustration anyway.
- **Pinned `build_62.py` before touching anything**, second lesson running. Note the asymmetry:
  the three tracked files verify against the commit with `git show | diff`, but `verify_62.cpp` is
  gitignored so its pin is only a working-tree copy — weaker provenance, take it early.

## What this session predicts for 6.4

**6.4 — Cook–Torrance, derived.** The centrepiece, and the lesson the golden breaks.

Open on 1.1386 again — 6.3 restated it and left it standing on purpose, because normalising *D*
does not couple the lobes. **Fresnel is the coupling**: F says what fraction bounces off the
interface, and only 1 − F is left to go in and scatter back out.

Derive the **4(n·l)(n·v)** denominator (a Jacobian, `dω_h/dω_l = 1/(4(v·h))`) rather than quoting
it — 6.3 deferred it explicitly. Fit Schlick against the exact Fresnel equations and state the
error, the same treatment 6.3 gave `s = 2/α² − 2`. F0 replaces `specular::colour`, and the metallic
workflow arrives as a *consequence*: metals just have coloured F0 and no diffuse lobe.

**Change the constant and the materials in the same commit** — 6.3 measured that the specular
colours absorbed a 17× error. Re-baseline the golden properly: diff, per-channel magnitude, old
hash `905BF27E` beside the new.

`build_63.py` pins nothing and lists `microfacet.hpp` whole — the file 6.4 is *about*. Pin first,
and take `verify_63.cpp`'s pin early since it is gitignored.
