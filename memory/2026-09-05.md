## The design, in five decisions

1. **One mechanism.** Every binding contributes a signed float; an action's value is the sum. A
   button, an axis from two keys and a scaled mouse delta are the same thing. Holding both halves
   of an axis gives **exactly 0** — a two-kind design would have needed a documented rule.
   Deliberately **not clamped**: two keys on a button sum to 2 (`held()` does not care) and a
   mouse flick *should* be big.
2. **Edges from the action's LEVEL, never a binding's.** Key+mouse on one action: press one while
   holding the other → binding-derived gives a second press and a **double jump**. Invisible with
   one binding, which is what a first implementation and its first test both have.
3. **`consume_pressed()` for the fixed step.** `pressed()` in `on_fixed_step` fires twice on a
   two-step frame *and* is lost on a zero-step one. Queue is **4 deep, overflow dropped** — a
   decision, since an unbounded queue replays jumps after the player stopped asking.
4. **`on_input()`.** None of the seven existing hooks runs exactly once *before* the simulation.
   `on_frame` is the near miss — right frequency, wrong place, 16 ms of input delay.
5. **A concept, not an interface.** `input::update()` samples SDL's live state, so the test could
   not otherwise exist. Beats an ABC three ways: changes nothing in `input.hpp`, no virtual call
   on a per-binding-per-frame loop, and open (`engine::input` satisfies it unknowingly).

**Declined: gamepad support.** Could not be run here; untested device code is a liability that
looks like support. §7 gives the five steps, an ⚠ VERIFY on the SDL3 signatures, and notes that
the hard part (disconnection) belongs in the *snapshot*, not the mapper.

**This lesson measures nothing and says so.** Attaching a number to a decision the number did not
make is worse than no number.

## The design, in six decisions

1. **Two files, because the include lists must differ.** `debug_lines.hpp` includes maths, a
   colour and the standard library and nothing that can draw. Put the queue in `debug_draw.hpp`
   and a physics TU compiles the framebuffer, the depth buffer and the handle system to draw a
   box. Hence `wire_mesh()` takes two spans, not `mesh`.
2. **The old functions became the backend.** `draw_debug_lines()` is a four-line loop over
   `line3_world`, which has clipped correctly since 3.3. A queue was put *in front*; nothing was
   rewritten, which is also why the golden survived.
3. **Expiry tests before it subtracts.** Measured in `float` at 60 Hz on a 0.5 s line: test-first
   31 advances, subtract-then-`<=` 30, subtract-then-`<` 30 **and keeps a one-frame line for ever
   at `dt == 0`**. Testing first removes the dependency rather than getting it right.
4. **Bounded (4096) with a drop counter**, one private `push()`. A bound with no counter is a bug
   that presents as a rendering artifact.
5. **ImGui PUBLIC where stb is PRIVATE** — *concept versus vocabulary*. The containment is a rule
   about which code may speak it (tooling only), and exactly one engine TU includes `<imgui.h>`.
6. **`masked_input`, not event routing.** Both consumers see every event; the arbitration is on
   levels, one layer later. `action_map` unchanged to the character.

**Declined:** the SDL_GPU backend (real signatures given, an exercise), depth-tested lines, and
batching — each named in a "What We Did Not Build" section rather than discovered later.

- **`box_sample` destroys a line drawing.** A 1-pixel line in a 3×3 block contributes one ninth of

# Third item — Lesson 6.1: Linear and sRGB (The Gamma Lesson)

Module 6 opens. **57 of 95 published.**

## The finding, which is the lesson

**The engine's GPU path had been displaying the wrong picture since Module 4.** Not subtly: linear
0.5 was stored as code **128 where 188 was meant**, and expressed as emitted light the error is
**13x in shadow and 1.1x near white**.

Cause: SDL claims a window with `SDL_GPU_SWAPCHAINCOMPOSITION_SDR`, whose own header says *"pixel
values are in sRGB encoding"*, and `scene.frag.hlsl` has returned linear **light** into it since
4.8. An input edge with no output edge.

**And Lesson 4.8's comparison sat directly on top of it and reported 87% byte-identical
agreement** — because `verify_48` created its render target as `R8G8B8A8_UNORM_SRGB` while the
program renders to the swapchain, which was `UNORM`. One enum, and it was the entire subject.

## What was produced

- **`gpu_device.{hpp,cpp}`** — asks for `SDR_LINEAR`, reads the format back, and records
  `gpu_report::composition` + `output_encodes_in_hardware`. `name_of(SDL_GPUSwapchainComposition)`.
  `is_srgb_format` promoted out of an anonymous namespace in `gpu_present.cpp` (two callers now).
- **`set_present_mode()`** — carries `report_.composition` instead of a literal `SDR`. A latent
  second instance of the same bug, three functions away: it would have undone the fix on the first
  vsync toggle.
- **`gpu_uniform.hpp`** — `pad2` → `encode_output`. **Zero bytes, zero repacking**: HLSL's packing
  had already reserved the slot, so 4.6's `static_assert`s did not move.
- **`scene.frag.hlsl`** — the exact piecewise curve when `encode_output > 0.5`.
- `scratch/probe_61.cpp` (throwaway, kept), `verify_61.cpp` (**34 checks**, 7 sections),
  `figs_61.py` → 6 SVGs, `build_61.py`, `l61_body_{a,b,c}.html`,

## Traps worth remembering

- **An error that is a RATIO hides.** 13x in shadow, 1.1x near white — the bright half looked
  nearly right and the dark half read as a deliberate moody grade. When a defect survives a long
  time, ask what *shape* it had.
- **A test that constructs its own environment tests the environment it constructed.** 4.8's
  harness and the shipped program differed by one enum. The fix is not "be careful" but to make
  the production value a readable field so a harness can assert on it.
- **Ask, set, then READ IT BACK.** The third call is the one people skip and the only one that
  reports what happened.
- **A two-parameter setter must pass through the parameter it is not changing.**
- **`pad2` was never wasted space** — padding created by an alignment rule is an unused field.
- **Inline KaTeX fails `check-page.js`**, again. Seven `\(…\)` gave `katexRendered: 10` against
  `eqBlocks: 3`. Already in the pipeline notes; still made.
- **A new listing tag needs the CSS rule AND `check-page.js`'s allowlist** — and the CSS first.
- **When a label cannot find clear space among the data, stop looking among the data.** Figure 1's
  curve label sat on something at two different interior positions; it belonged in the text column.
- **Write the throwaway probe first.** `probe_61.cpp` established every fact before a word was
  written. Reasoning found the bug; the probe made it a claim.
- Two harness bugs of my own: `render_flat` passed a **null sampler** (the renderer binds a white
  1x1 fallback for untextured items, and a binding is a texture *and* a sampler — segfault inside
  SDL), and I `cd`'d into `build/demos` in the run script, which broke §G's repo-root-relative
  paths. Every other harness runs from the root; `SDL_GetBasePath()` finds the shaders regardless.

## Next

**6.2 — Radiometry-Lite and What a BRDF Is.** 6.1 settled the units; 6.2 asks what the quantity
is. Radiance is what a pixel measures; a BRDF is a *ratio* with units of inverse steradian; and
**the π in Lambert's albedo/π is the part to derive** — it falls out of integrating a constant
BRDF over the hemisphere and demanding energy conservation. This engine currently hides that π in
the light's intensity without saying so, and `light.hpp` should be made honest.

**The golden is genuinely at risk this time**, for a statable reason rather than a guessed one: if
the π lands in the BRDF, every shaded pixel moves. Re-baseline deliberately — diff, per-channel
magnitude, old hash `905BF27E` beside the new — and say in the lesson that the old picture was not
wrong, it was parameterised differently. `build_61.py` pins nothing and lists `scene.frag.hlsl`
and `colour.{hpp,cpp}` whole; 6.2 will touch the first, so pin before editing.
