# 2026-08-26 — Collapsible code listings, and the grey "modified" badges

Two independent changes, committed separately. No lesson prose was touched and no lesson was
regenerated; both land entirely in `docs/shared/` and `docs/_template/`, plus a mechanical
attribute fix in 14 published pages.

## 1. The grey badges (committed first)

`course.css` carries two parallel badge vocabularies — `.badge` with `new`/`mod`/`done`/`soon` for
manifest tables, `.tag` with `new`/`modified` for listing caption bars. The builders' `LISTING_META`
stored `("mod", "modified")`, reaching for the `.badge` spelling while emitting into a `.tag`
context. The result, `<span class="tag mod">modified</span>`, reads correctly and renders the right
word but matches no rule, so it fell back to the bare `.tag` grey `#3a3f4c` instead of amber
`#453a1c`. **82 badges across 14 pages** (lessons 3.7 → 5.1 — every builder-generated page) were
grey while the 144 hand-authored ones were amber, often in the same page.

Fixed at the source rather than aliased: 66 tuples across the 14 `scratch/build_*.py` builders, and
the 82 occurrences in HTML via one exact substitution (every instance was the byte-identical string
`class="tag mod">modified<`, so the diff is 82 lines that differ only in the class attribute).

`scratch/` is gitignored, so **the commit contains only the 14 HTML files** — the builder edit is
local hygiene that stops the next rebuild reintroducing it.

Guard added: `check-page.js` now reports `unknownTagClasses` for any `.tag` modifier outside
`new`/`modified`. Negative-tested — reintroducing the bug in the live DOM fires it and flips
`pass` to false, and the two spellings really do compute to different backgrounds
(`rgb(69,58,28)` vs `rgb(58,63,76)`).

## 2. Folding long listings

CLAUDE.md §8 forbids placeholders, so lessons print whole files. Lesson 5.1 carries 9,444 lines
across 34 listings; `demos/sandbox/main.cpp` alone is 5,727 of them, 61% of the page.

**Key insight, and the reason no lesson HTML changed: `max-height` is a no-op on elements already
shorter than it.** One rule on `.listing pre` retrofits all 798 listings across 50 pages, clipping
only the ~230 whole-file ones. Safe to automate because listing lengths are sharply bimodal —
median 9 lines, p75 74, and the fold count barely moves between thresholds of 24 and 60 (233 → 209),
so almost nothing sits near the boundary.

Design decisions worth not re-litigating:

- **The clamp must be CSS, not JS.** `course.js` is a classic script at end of body, so it runs
  after the browser has painted. Collapsing the document height there breaks anchor jumps and
  scroll restoration. Measured: JS now changes total page height by **33px** across all of
  Lesson 5.1, from one 13-line listing being released.
- **`<details class="listing">` was rejected.** Semantically better, but it hides content with
  `display: none`, which silently breaks the `getComputedStyle(.listing pre)` probes in
  `check-page.js` (`sharedCssApplied`, `wrappedListings`) — and it would mean rewriting 798 blocks.
- **Decide by line count, never by measuring.** `textContent` needs no layout, so it is right
  before webfonts settle and right for the one listing in the course nested inside a closed
  `<details>` (`01-07-vectors-2d.html`), where `scrollHeight`/`clientHeight` both read 0 and any
  measurement calls a long file "short".
- **The bottom bar is `position: absolute` while collapsed**, so adding it costs zero layout shift.
  Verified: removing every injected bar changes document height by exactly 0px.
- **No expand animation.** `max-height: none` cannot transition, and faking it with a pixel value
  means a 100,000px transition on the longest listing.

Peek is 12 lines (`--listing-peek-lines`), fold threshold 14 — two lines of slack so a 13-line
listing never gets a bar that costs more than it saves. `--listing-line` duplicates
`0.79rem * 1.62` from the rule below it because a custom property cannot read another rule's
computed font-size; the coupling is commented in place. Opt out per listing with
`class="listing nofold"`.

Because find-in-page can match clipped text but not scroll to it, the masthead gained an
**Expand all** button — *injected* next to `#theme-toggle` rather than authored, since the masthead
is hand-copied into all 50 pages. Persists in `localStorage` under `engine-course-listings`;
`#expand-all` opens a page without writing the key.

Lesson 5.1 collapsed is **42,763px vs 252,780px expanded — 16.9% of the original.**

## Trap worth remembering

`course.css:184` sets `scroll-behavior: smooth`. Any Playwright anchor test that navigates and
waits a fixed few hundred ms will catch a 36,000px scroll mid-animation and report a false failure.
Use `reducedMotion: 'reduce'` on the context, or wait for `scrollY` to stop changing.

# 2026-08-26 (later) — The four pre-existing check-page failures

Cleared all four. **The corpus now passes 100/100 page-checks** (50 pages × 1280px and 390px) —
the first time every page has been green at both widths.

## Two SVG label collisions (`svgTextOnShape`)

- **`00-06` figure 2** — the second "observe" label sat centred at x=352 with a box spanning
  333.5..370.3, and the vertical arrow it labels is at x=335, so the arrow ran through its first
  glyph. Moved to x=360 (box 341.5..378.3), giving 6.6 units of clearance to match the 5.5 its
  sibling label has from the horizontal arrow. **Note both labels read "observe"** and
  `check-page.js` dedupes by `figure|text|tagName|class`, so a single report could have meant two
  collisions — measured both; only the second was hitting.
- **`01-02` figure 1** — the row-2 gutter label `SDL_EVENT_KEY_DOWN` is 131 user units wide but the
  gutter (x=10 to the timeline origin at x=100) is only 90, so it ran past the axis into the t=0
  event spike. Wrapped onto two `<text>` elements, house style (the corpus uses separate `<text>`
  for multi-line, not `tspan`/`dy`). `xs` would still need 113 units, and right-anchoring pushes it
  to negative x and trips the viewBox-spill check instead.

## Two horizontal-scroll failures (`pageScrollsX` at 390px) — both root-caused in the shared sheet

Neither was a page bug; both were missing CSS, so both fixes are one rule each in `course.css` and
they clear latent breakage well beyond the two pages that happened to fail.

- **Bare `<pre>` had no overflow rule.** `overflow-x: auto` hung on `.listing pre`, but transcripts
  in pitfall callouts and `.worked` boxes are bare `<pre>` with no `.listing` wrapper — they
  computed `overflow-x: visible`, so a 677px compiler error inside a 302px column spilled and
  dragged the page sideways. Moved the declaration to plain `pre`. **6 blocks across 3 lessons**
  were spilling at 390px (`00-03`, `00-06`, `03-01`); only `03-01`'s was bad enough to trip the
  check.
- **`p.mono` never had a rule at all.** Confirmed against full git history: the markup was authored
  from Lesson 3.3 (2026-07-29) onward and no declaration was ever written. All **16 blocks across
  `03-03` and `03-04`** — hand-aligned numeric walkthroughs, columns padded with `&nbsp;`,
  continuation lines indented under an `=` — rendered in the body serif at 18px. No alignment, and
  wide enough to push the page sideways. Added `p.mono` with `font-mono / 0.79rem / 1.75`,
  `white-space: nowrap` and `overflow-x: auto`.

  **`nowrap`, not `pre`**: these blocks break lines with `<br>` and pad with `&nbsp;`, so whitespace
  must still collapse — `white-space: pre` would render the source file's own indentation. `nowrap`
  keeps the collapse, refuses to re-wrap a numeric column, and lets `overflow-x` scroll it on a
  narrow screen, the same bargain every listing makes.

  Watch the neighbour: `figure.dia svg .mono` is a *different* class in a different context and only
  sets the family. Its existence is probably why the missing prose rule read as deliberate.

Print rule extended to release `pre, p.mono` overflow, not just `.listing pre`.
