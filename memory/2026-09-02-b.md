## The design, and the part not to re-litigate

**No reference counting**, argued from 5.4's properties: a count needs a copy ctor, a dtor and a
store pointer, costing 4 bytes / trivially copyable / memcpy-into-a-component / serializable
without fixups. A refcounted handle is a `shared_ptr` with extra steps. So **explicit unload**,
safe to get wrong *because* staleness is detectable — forget → leak (a total finds it), unload
early → null + `collect_stats::unresolved`. Neither is a crash.

**Derived assets are the one unavoidable rule**: owned by their source, cascading
**transitively**, refused from a dead source. This closes 5.4's deliberate hole. The sandbox
cache's eviction is now one line (`store.meshes().contains(slots_[i].cpu)`).

**Import settings are identity.** Key = name + settings, and **the default must serialise to
nothing**.

**Not a singleton**: sandbox holds three stores.

## Three things that went wrong, all kept

**Double-logging a refused name.** The first smoke run produced two errors for one failure —
`search_path`'s (says why) and `asset_store`'s (says less). 5.3's own rule, broken by the lesson
after it. `resolved_path::refused` lets the caller tell "already reported" from "mine to report".

**Two key spaces wearing one name.** `verify_55` §D, one check after the one that stored the
asset: `insert_mesh("cube")` → `"cube"`, `find_mesh("cube")` → `"cube|flip=1"`. Silent, no crash.
Fixed by making the *default* import encode to nothing — same shape as generation 0 being
reserved.

**The measurement double-counted.** First version stacked `read` beside `parse` (`load_obj` opens
the file itself) and stacked `validate` (which the store never runs): 6.20 ms for a 3.69 ms
operation. Correcting it produced the better finding — the acquire *is* the parse — and exposed
the demo's validation cost.

## Traps worth remembering

- **`SDL_GetPathInfo(path, NULL)`** is the documented existence check and fills in `size` for
  free. Require `SDL_PATHTYPE_FILE` or a directory of the right name is a hit.
- **A member function hides a namespace-scope one**: `asset_store::load_image` vs
  `engine::load_image`. Second lesson running (5.4: member `handle()` vs type `handle<T>`).
- **Collect then recurse** when a cascade erases from the vector it walks — correct with one
  dependent, which is every case the demo has.
- **`verify_54` broke and was right to**: `load_model` no longer frees. Updated to assert the new
  contract *with the reason written next to it*.
- The software HUD is full at 14 px rows; the asset counters went to the **log** instead, printed
  on every acquire and unload. A number squeezed into another lesson's row is a number nobody
  reads.
- Two figure defects again caught only by `shot-figs.mjs`: a divider through prose (5.4) and two
  adjacent text runs with no space between them (5.5, fig 6).
