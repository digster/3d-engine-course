## The design, in five decisions

1. **The colour space goes on the TEXTURE**, not the sampler and not a second `sample`. Settled by
   the hardware rather than taste: SDL_GPU declares the decode in the *format* and performs it in the
   sampler, so one image cannot be sRGB in one binding and linear in another. 3.9 built these types
   to mirror SDL_GPU's, and **mirroring includes mirroring where a decision lives.**
2. **The space is part of the asset's IDENTITY** — 5.5's `mesh_import` rule, second type. Two
   textures, one decode, keys `name` and `name|linear`, and the default serialises to nothing.
3. **A tangent is a `vec4`.** The handedness is stored and the bitangent is not — 12 bytes saved, but
   the *reason* is that a recomputed bitangent cannot disagree with the interpolated N and T beside
   it. Same argument as `material::textured()`.
4. **A tangent takes the model matrix.** 3.6's distinction on its other side: a normal is defined by
   being perpendicular, a tangent lies IN the surface and is a difference of positions.
5. **A vertex layout is per-pipeline state.** `describe(desc, slot, with_tangent)` rather than
   renumbering every consumer — a shader that reads no tangent should not declare one.

## Traps worth remembering

- **THREE OF THE HARDEST BUGS HERE PRODUCE A PLAUSIBLE PICTURE.** A sRGB-read normal map reads as
  "authored too strong"; a dropped handedness reads as a modelling error; the wrong matrix reads as
  an asset authored at the wrong angle. Each has a plausible wrong *fix* that makes the picture less
  wrong without making it right. That is the argument for a type or an assertion over a comment.
- **The GPU had `create_sampled(…, srgb)` since 4.7 and the CPU had no concept at all.** Same shape
  as 6.6's `load_image`/`sample` gap — two halves of one idea with no path between them, invisible
  to every test because there was no wrong behaviour, only absent behaviour. **Two lessons running,
  so it is a habit now: look for subsystems that ought to compose and never have.**
- **THREE ASSERTIONS WERE WRONG AND THE CODE WAS RIGHT**, all from typing a number instead of
  deriving it. §A's `srgb_to_linear(128/255)` (0.21586, not the 0.21404 I remembered from 6.1); §D's
  exact round trip (0.5 IS NOT AN 8-BIT CODE — the floor is 5.546e−03 and every flat normal map

## What this session predicts for 6.8

**6.8 — Shadow Mapping: Bias, Acne, and PCF**, and the framing that matters is *not* "render from
the light". It is that **the comparison is between two floats computed differently** — one
rasterised from the light's viewpoint, one rasterised from the camera's and then projected into
light space. Their disagreement IS shadow acne, so the bias has to be derived from that rather than
introduced as a fudge: the projection's non-linear depth distribution (2.10, and 4.9 measured it)
explains why the error grows with distance, and the slope dependence explains why a constant bias
gives peter-panning at grazing angles and acne at steep ones.

And **normal-offset bias is the other answer** — move the sample point along the normal instead of
the depth — which is the first time 6.7's new fact will matter: the engine now has a shading normal
that *disagrees with its geometry*.

Four things the engine lacks: a depth-only pass (4.8's three-pipelines shape to copy), a light-space
matrix (`directional_light` has no position, so the orthographic frustum must be fitted to scene
bounds — `gltf_view` already computes those and that code wants to be in the engine), a depth texture
that can be *sampled* rather than only attached, and a comparison sampler for PCF —
⚠ VERIFY `enable_compare`/`compare_op` against `SDL3/SDL_gpu.h` before writing them.

Show the artefact first (CLAUDE.md §3.5): acne is one of the most photogenic failures in the course.
And the golden should stay E917C06C for a seventeenth lesson — shadows are a new path, and if it
moves, something was wired into the default that should have been opt-in.

`build_67.py` pins nothing while listing `texture.hpp`, `mesh.cpp`, `material.hpp`,
`scene.frag.hlsl` and `verify_67.cpp` whole. Pin before writing a line, and take `verify_67.cpp`

## The lesson in one line

**Shadow acne is not a mystery, it is a sampling error with a computable magnitude**: the map stores
one depth per texel and the fragment is somewhere else inside it, so half of every texel's footprint
is downhill of its own sample.

## Traps worth remembering

- **A REGULAR SAMPLING GRID ALIASES AGAINST A REGULAR TEXEL GRID.** §C's first version reported
  **3.3%** acne where the truth is 50%, and a worst error at 22% of a bound that is actually tight —
  because a 96×96 grid over the plane came out at 4.8 shadow texels' spacing, so every sample landed
  at nearly the same sub-texel position. Fixed with a **Weyl sequence** (golden-ratio stride). It is
  the same aliasing the shadow map itself suffers from. **A number that disagrees with your eyes
  deserves suspicion in both directions.**
- **`round`, not `floor`.** This rasterizer evaluates attributes at *integer* pixel coordinates, so
  the nearest stored sample is `round(x)`; hardware samples at pixel *centres*, where the texel
  containing the uv is the same thing. Get it wrong and every offset is biased half a texel, the
  reach doubles, and the derived bias is half what is needed.
- **THE REACH DEPENDS ON THE KERNEL.** A 3×3 reaches 2.12 texel-diagonals, not 0.71. A correct bias
  stops being correct the moment PCF is switched on — and the acne arrives *looking like a filtering
  bug*. Found by rendering, not by reasoning.
- **`verify_48` had a stale assertion**, `sizeof(scene_light_uniforms) == 64`, under a message
  claiming to check register packing. **An assertion stricter than its own message fails correct
  code.** Repaired to `% 16 == 0` plus a separate exact-size check.
- **Two of 6.7's predictions for this lesson were wrong**, and saying so is cheaper than quietly
  dropping them: `material.hpp` needed no shadow-casting flag (casting is a property of the DRAW
  LIST, expressed as a subspan), and `texel_space` needed no third value (a CPU shadow map is a
  `depth_buffer` of floats, not a `texture` of `Uint32`). Only `scene.frag.hlsl` was certain.
- **And the plan's framing was wrong too.** Non-linear depth is a *perspective* problem; an
  orthographic light spreads depth evenly, so the quantisation term is constant across the map. It
  returns for spot lights. Corrected in the lesson in a callout rather than silently.
- **zsh does not word-split unquoted `$var`.** Two rounds of demo renders came out identical because
  `$FLAGS` was passed as one argument. The renders looked "correct" — which is why the pixel diff was
  what caught it, not the eye.
- **The course embeds no raster images.** The acne artefact had to be an inline SVG mock; its
  fringes are computed as level sets of a projective coordinate, which is why they swirl.
- **`.eq` divs must contain KaTeX.** `check-page.js` requires `katexRendered === eqBlocks`, so six
  code-only `.eq` blocks failed the page silently at 390px with no printed reason.
- **Pinned `build_67.py` before touching anything**, seventh lesson running; the rebuild diff was
  exactly the two nav lines.

## What this session predicts for 6.9
