## The decisive fact, and it came from reading SDL

`src/SDL_log.c` initialises priorities from `app=info, assert=warn, test=verbose, *=error`, and
`SDL_LOG_CATEGORY_CUSTOM` is where applications begin. **So every category we invent defaults to
ERROR.** Moving the engine off `SDL_LOG_CATEGORY_APPLICATION` makes it quiet with no
configuration and no filter code — which is 5.2's "don't wrap a library you won't replace"
policy paying out a second time, harder. A wrapper would have reimplemented that and got a
different answer.

`./build/demos/pong` now prints ONE line, its own. `--log platform=info` brings the engine back.

## Three things that went wrong, all kept

**`ENGINE_VERIFY` was wrong and measurement found it.** v1 gated on `NDEBUG`; SDL gates on
`__OPTIMIZE__`. At `-O2` with no `-DNDEBUG` it took the `SDL_assert` branch at level 1 =
`(void)sizeof(cond)` — an unevaluated context — so the macro whose purpose is guaranteed
evaluation stopped evaluating. **4 bytes: a bare `ret`.** Fixed by evaluating into a named bool
always and gating only the check, on `SDL_ASSERT_LEVEL`.
*General rule: when you gate your machinery on a build flag, find out what your dependencies gate
theirs on.*

**`measure_53`'s first run was fine but `--trace` broke.** The GPU command log lives on the `gpu`
category, which 5.3 just silenced, so `--trace` would have printed nothing. One line in sandbox:
the flag that asks for the report also raises the level. *A diagnostic switch that silently does
nothing is worse than no switch.*

**Two figures wore each other's captions.** `build_53.py` mapped `FIG_REPORT → l53_fig5.svg`
while `figs_53.py` wrote `l53_fig5.svg = fig_build_matrix`. Every automated check passed. Only the
screenshot caught it. Fix: number SVG filenames by PAGE order and keep the generator's dict in
that order too.
