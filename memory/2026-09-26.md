## Findings, in the priority order proposed

1. **Three wrong third-party claims**, verified at source. The engine's own defaults still stand;
   only the comparisons are wrong.
   - Gyroscopic, "Bullet and PhysX both ship it off": Bullet is ON by default since 2.83
     (`m_rigidbodyFlags = BT_ENABLE_GYROSCOPIC_FORCE_IMPLICIT_BODY`); PhysX opt-in is right. In
     `phys/rigid_body.hpp:195`, 8.3 prose and listing, 8.10 listing, `conventions.html:3603`, STATE.md.
   - Friction, "Box2D, Bullet and PhysX all ship sqrt(a·b)": Bullet multiplies (a·b, clamped to 10);
     PhysX averages (`eAVERAGE`). In `phys/solver.hpp:241`, 8.9 prose (~l.1689), listings 8.9–8.12.
   - Restitution threshold, "1.0 is the number every engine ships": Bullet 0.2 m/s; PhysX
     0.2 × `PxTolerancesScale::speed`. In `phys/solver.hpp:514`.

   Fixes must reach the builder fragments and pins as well as the HTML, or a rebuild reverts them.
   Closable ⚠ VERIFY flags, checked against SDL 3.4.12: 0.5 `data1`/`data2` (`Sint32`); 2.11
   `SDL_GPUViewport` (x, y, w, h, min_depth, max_depth); 5.10 `SDL_GetGamepadAxis` → `Sint16` and
   `SDL_GetGamepadButton` → `bool`; 0.2's "before Module 4 uses this for real".
2. **Length and hours.** Prose per lesson: M0 4.6K words → M7 13.9K → M8 14.8K (spec 3,000–7,000).
   8.5 is 64 screens at 1280×900 and ~110 at 390. M8 lessons add 1,100–3,000 lines of code each on a
   5–6 h budget; a rough model (150 wpm, 250 lines/h, no time for exercises or debugging) needs
   ~560 h for the published lessons against 468 h estimated, M8 at ~2×. Proposal: measurement
   ledgers behind `<details>`, and a core path that reads at Module 1's pace.
3. **20 lessons have hints but no solutions** (§6 requires both): 4.5–4.9, 6.6–6.8, 6.14–6.16, 6.18,
   7.4, 7.8, 8.1, 8.2, 8.4–8.7.
4. **The authoring pipeline is untracked.** `scratch/` (378 MB, gitignored) holds ~33 MB of real
   source: 64 builders, 80 figure generators, 230 body fragments, 475 SVGs, 474 pinned listings
   (13.8 MB — pinning by `git show <sha>:path` would replace them), 110 harnesses. The tracked
   `check-builders.py` depends on all of it. Process docs have outgrown their jobs: STATE.md 838 KB
   (~210K tokens; its `updated:` header alone is ~130 lines), LEARNINGS.md 566 KB, ARCHITECTURE.md
   252 KB, README.md 130 KB.
5. **macOS-only verification.** No CI; no GCC or MSVC build on record; no DXIL ever produced; SPIR-V
   compiled but never run — only Metal executes. Proposal: an Actions matrix with `-Werror`, plus
   headless runs (SDL's dummy video driver, lavapipe, WARP), before 9.10 promises three-platform
   packaging.
6. **Style guide vs build.** The guide says exceptions and RTTI are off, but the engine builds with
   only `-std=c++20 -Wall -Wextra`; it says ".clang-format decides" and "CI turns it on", and neither
   exists; `audio/mixer.cpp:249` holds a raw owner; public headers run 2.86 comment lines per code
   line (24.8K vs 8.7K) with 116 `verify_NN`/`scratch/` references in engine and demo code, against
   the guide's own "course explanations belong in the prose"; no tracked tests before 9.9.
7. **Engine gaps for a shippable game.** Only `directional_light` (no point or spot lights, no
   attenuation, no spot or cube shadows); no compute pipelines anywhere; glTF import keeps position,
   normal and UV only (no skins or clips, `gltf.cpp:293`); no world-level raycast or overlap query and
   no static triangle-mesh collider (the broadphase only builds pairs); no gamepad (declined in 5.10);
   point-resolution rendering on Retina (explained in 4.2, never revisited). Suggested insertions:
   6.9b, 7.7b, 8.14.
8. **Module 9 is over-committed**: 11 lessons, ~57 h, with estimates written before the M8 standard;
   9.10 fits packaging on three platforms, API docs and a docs site into 4 h. Proposal: 14–16
   lessons, and split 9.10.
9. **Reader polish.** `index.html:181`'s hero SVG says "STAGE B · Modules 4–8" (inside SVG, so the
   renumber sweep and the checker both missed it); the index's done-list lags CLAUDE.md §12's physics
   contract; Conventions (~26K words, 48 sections) is called "short" and labelled "Read before
   Module 2" — it needs a one-screen cheat sheet; figure labels render at ~4 px at 390 (~8.7 px at
   1280, body text 20 px) while `check-page.js` passes; ~220 "N.M §X" cross-references, 6 of them
   links; no git tag per lesson; published index cards are paragraph digests (the index is 32K
   words); a stray empty `docs/lessons/scratch/l33`.

## Instrument mistakes

- A zsh helper built on an unquoted `$E` holding `git ls-files …` returned a false zero for every
  capability probe — zsh does not word-split parameters. Redone in Python.
- A section regex `<h2…>(?:<[^>]+>[^<]*)*?Exercises` crossed `h2` boundaries and swallowed whole
  pages, so lessons looked exercise-free. Splitting on `(?=<h2\b)` first fixed it.
- The first figure-size estimate assumed a default font size for class-styled labels. The real
  measure is computed `font-size` × rendered width ÷ viewBox width: 11 px × 330/900 ≈ 4 px.

The review's own artefacts (`.playwright-mcp/`, the scratch build) were removed afterwards.
