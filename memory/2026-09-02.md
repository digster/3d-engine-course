# 2026-09-02 — Lesson 5.4: Handles: Generational Indices

## What was produced

- **`engine/core/handle.hpp`** — `handle<T>`, one 32-bit word split 20 index / 12 generation,
  packed generation-high. `T` is a **phantom** parameter (nothing stored, `sizeof` is 4, `T` may
  be incomplete), so `handle<mesh_data>` and `handle<texture>` are different types.
  Generation 0 reserved ⇒ all-bits-zero is the null handle, free.
- **`engine/core/pool.hpp`** — `pool<T>`: `slots_` sparse+stable, `items_` dense+mobile,
  `owners_` mapping back. `slot::dense == 0xFFFFFFFF` IS the occupancy flag. insert/remove/
  get/contains all O(1); removal is **swap-and-patch**.
  Both header-only ⇒ **no CMake change at all**. 42 → **44** public headers (counted).
- `mesh.hpp` gains `mesh_handle`, `mesh_pool`, `to_mesh_data()`; `scene_object::geometry` is a

- `demo::mesh_library` replaces four hand-owning workarounds; `build_floor` / `load_model` now
  remove-then-insert.
- `scratch/`: `verify_54.cpp` + `build_verify_54.sh` (68 checks, 7 sections, two build configs),

## The shape of the argument

The motivation was **already in the repository**, written by us: `hello_cube`'s "the data must
outlive every frame that uses it", `model_state`'s "safe because of the order two things happen
in", and 4.8's five-field cache key whose own comment called it "the shabby version of" a handle.
Three admissions, one cause — nothing is ever destroyed — and 5.5 ends that.

**Derive from three failures, in order**: dangling, aliasing (ABA), relocation. The turn is that
a **bare index makes aliasing WORSE** — a probable crash becomes a guaranteed silent wrong answer
— which is what motivates the generation rather than decreeing it.

**Bump on removal, never on insertion.** A vacated slot then already carries a value no
outstanding handle holds, so no separate occupancy window exists to guard.

## Decisions worth not re-litigating

- **Dense storage, not a slot-indexed array**, at ~30 extra lines: sparse iteration is exactly
  what 5.6 measures, and swap-and-patch is the only thing that *proves* a handle is not a pointer
  (a live object's address changes and its handle still works).
- **LIFO free list**, knowing it concentrates generation churn on one slot. FIFO is the
  documented fix and is Exercise 9.3.
- **Rebuilds replace rather than overwrite in place.** Overwriting would keep the handle valid
  and make the change invisible — wrong when something caches per mesh.
- **No global pool.** `sandbox` ends the lesson with **two** `mesh_pool`s in one frame (loaded
  geometry, and geometry derived by `with_normals`), which is the concrete refutation.
- **Did not fold in 5.3's residue** (61 bool returns, three status enums). Still open.

## Kept honest rather than hidden

- §D of the harness **exhibits the wrap**: 4,095 recycles of one slot, then the original handle
  resolving to the new occupant. 12 bits buys the failure down, it does not remove it.
- The API cost is named: `collect_triangles` went 8 → 9 parameters, one lesson after 5.1
  celebrated 15 → 8.
- 5.4 **left a lifetime hole for 5.5 on purpose**: the cache's two pools have no rule connecting
  them, so freeing a source leaves its derived mesh alive keyed by a dead handle.

## Traps worth remembering

- **A member function named `handle()` blocks the type `handle<T>`.** `gpu_device::handle()` and
  friends make unqualified `handle<mesh_data>` fail with "explicit qualification required to use
  member 'handle' from dependent base class". Verified in four lines. Always use the alias.
- **`pop_back()` does not free what a moved-from element owned** — a moved-from `std::vector` may
  keep its buffer. Assign `T{}` before popping or the pool holds freed meshes forever.
- **Guard the self-move** in swap-and-patch: `dead == last` is the *common* case (removing the
  last element), and self-move-assignment may empty the object.
- **`verify_50` broke, and instructively.** It hand-built a `scene_object` with
  `geometry = icosahedron_mesh()`. Minting a handle in the harness would have produced one the
  render's own pool could not resolve (5.4's own Pitfall 5, the same afternoon). Correct fix:
  `override_object` carries a `mesh` **view**, and `render_one` — which owns the pool — stores
  it. A struct that describes an object for somebody else to render cannot carry a handle.
- **Count, do not increment.** 5.3's STATE said "43 public headers"; `find | wc -l` says 42 before
  this lesson and **44** after. Corrected in STATE, README and ARCHITECTURE. Any number a one-line
  command can produce should be produced by that command every time it is written.
- **`mesh.hpp` gained a transitive SDL dependency** (via `pool.hpp` → `log.hpp`). Harmless —
  all 44 headers still compile standalone — but a container template pulling in logging is free
  only until somebody wants the container where SDL is not.
- **check-page.js does not catch text over a filled rect or a rule through prose.** Two figure
  collisions this session — row labels running into the first column, and a divider crossing a
  line of notes — were caught only by `shot-figs.mjs`. Third session running that the visual pass
  earns its keep.

## Next

**5.5 — The Asset System v1.** The mechanism exists; 5.5 is the policy: loading, *finding* (name
→ handle, loaded once), and **unloading** — the word this module has been building towards.
Design constraint is the hole above: **derived assets** (a texture and its mipmaps, a mesh and its
GPU upload) need a lifetime rule. Argue reference counting rather than assuming it. Convert
textures as the second subsystem. Test to beat: golden still byte-identical (fifth lesson),
same name twice ⇒ same handle and one load proved by a counter, unloading a mesh a scene still
uses shows up as `collect_stats::unresolved` and nothing else, and a derived asset must not
outlive its source. **Do not** let the asset system become a singleton because a handle needs its
pool.
