## Two facts measured before writing anything

Both could have made the lesson wrong, so both were probed first.

1. **The matrix crosses untouched.** The SPIR-V decorates it `RowMajor`, which looks like a
   transpose. Pushed a matrix with element (row,col) = 16·row+col+1 and read all sixteen back one
   pixel at a time: every one where our storage put it. **Lesson 2.6's claim survives.** The
   decoration is DXC's vocabulary, not a statement about bytes.
2. **The packing rule is HLSL's, not std140** — despite SDL's header citing std140. Measured
   offsets 64/68/80/84/**96**; std140 would say 80/96/112. SDL's advice is still right to follow
   because std140 is a *superset*.

## The failure, and its shape

Naive C++ struct puts the trailing `float3` at 92; shader reads 96. Wrote (241,242,243), got
**(242,243,0)**. A uniform layout bug corrupts the **tail** — mirror image of 4.5's pitch bug where
vertex 0 was always right. Both look fine at the start, for opposite reasons.

## A revision to 4.3, and a shader that had to be deleted

4.3 guessed a wrong register space would be silent. Actually: `glslc` accepts, reflection is
**byte-identical**, but SPIR-V→MSL **refuses** with an exact message. So the build catches it —
4.3's "compile offline" argument paying off unexpectedly.

I wrote a deliberately-space0 probe shader to measure this and **it broke the build**, which is
itself the finding. Deleted it: a file in the repo that does not build is a liability. `verify_46`
§D instead parses `DescriptorSet` decorations out of the shipped `.spv` — SPIR-V is a 5-word
header then `(wordcount<<16)|opcode`; OpDecorate=71, DescriptorSet=34. Twenty lines, no dependency.

## Three mistakes this session records

- **I published an incoherent number and caught it on re-read.** The push-cost table said 16 KB at
  43 GB/s against 4 KB at 3.8 — an 11× difference in a `memcpy`. Cause: rep counts scaled per size,
  one run each, first-touch dominating. Fixed with fixed reps + best-of-seven (minimum, because
  every error source adds time). 4.4's rule: check the number *can* be true.
- **The harness crashed the process** by repeating 64 KB pushes. That turned out to be a real
  finding (undocumented pool exhaustion, non-deterministic between 24 and 32 pushes, **no message
  at all**) — but per 4.4, a test that destabilises the process is not a test. Measured in an
  isolated program, reported in prose, handed to the student as an exercise.
- **A bare `<pre>` inside a callout scrolls the page.** `.listing pre` has `overflow-x: auto`; a
  `<pre>` anywhere else does not. Cost one round of `check-page.js` at 390 px. Either use a
  `figure.listing` or inline it as `<code>`.

## Also worth keeping

- The manifest table needs `tbl-scroll` too when paths are long (`shaders/uniform_probe.vert.hlsl`
  is enough to overflow at 390 px). 4.5 got away without it.
- `figs_46.py` imports the raster helpers from `figs_45.py` rather than copying them — safe
  because `figs_45` guards its writes behind `__main__`.

## The continuity catch

Changing `mesh.{vert,frag}.hlsl` **broke `verify_45`** — it draws with those shaders, and once
they wanted a uniform block it got a zero matrix and drew nothing. The fix was not to update 4.5's
numbers but to push **exactly the camera the deleted `static const` floats encoded**, so all of
Lesson 4.5's published figures stay reproducible: 3,696 / 5,076 / 5,027 / 3,126 / 1,990 / 9,944 /
32,006, every bounding box identical, and all six of its figure SVGs regenerate byte for byte.

**Run the previous lesson's harness whenever a shared shader or header changes.** A harness that
stops reproducing its own lesson's figures has quietly become a different experiment.
