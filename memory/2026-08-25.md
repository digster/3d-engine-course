## The lesson's shape

The port itself is bookkeeping and the lesson says so. The length went to the **audit** — fifteen
stages and what became of each — and to the two things the port forced out that were not in the
plan.

## Three things worth keeping

**The naive normal matrix changed zero pixels, and that is a theorem.** A box's model-space
normals *are* its axes; a diagonal scale sends an axis to a multiple of itself; `normalize()`
discards the length. So the bug is invisible on crates *by construction*, and a crate test scene
proves nothing. Fixed the experiment by squashing the icosahedron rather than by declaring the
measurement broken.

**"100% of pixels differ" meant nothing.** A flat untextured floor is one colour, and that colour's
blue (0.0045186) lands in the gap between our sRGB encoder's 14/15 boundary (0.004580) and the
hardware's (between 0.0045148 and 0.0045186). One disagreement, 39,202 times. Report a histogram.

**The first hypothesis was wrong and the refutation is in the lesson.** A 14-point sweep said the
encoders agreed; a float-target probe said the GPU fragment was bit-identical to `shade()`; only a
fine sweep across 0.0044–0.0050 found the gap. *A sweep is only evidence where it has samples.*

## Three harness bugs, all instructive

1. **A reference that has been simplified is not a reference.** The software comparison path had no
   near clipping, so it skipped both floor triangles (the near edge is behind the camera) and the
   GPU appeared to cover 35,532 extra pixels. Fixed by calling `engine::clip_polygon_near` — 3.3's
   code doing 3.3's job.
2. A pass begun without a depth attachment while its pipelines declared one — undefined, and it
   produced a perfectly plausible table.
3. The sweep resolution above.

## Also worth keeping

- **The `--gpu` flag inverted**, as 4.2 promised. `engine` / `--software` / `--probe`, with
  `--gpu` kept as an alias because six lessons tell the student to type it. The software path is
  the **reference** and is not going away.
- **The HUD was given up.** No `SDL_Renderer`, so no `SDL_RenderDebugText`; a GPU font is
  stb_truetype and Module 6. `[V]`'s split view is a better instrument, and the loss is stated in
  the lesson rather than glossed. Exercise 4.8.5 is the way back.
- **CSS beats inline `fill` on SVG `<text>`** — hit again. The `apply-shared.py` lint caught 38 of
  them; the figures now use `.t-ok` / `.t-hi` / `.t-bad` / `.muted` / `.lbl-x|y|z`, with the
  five-way distinction carried by the `<rect>` swatches, which *are* unaffected.
- **`pre class="snippet"` does not exist.** Short code blocks must be a
  `<figure class="listing">`, or the page scrolls horizontally at 390 px. Also: KaTeX display math
  must be in `<div class="eq">` and there must be **no inline `\(…\)` anywhere**, or
  `katexRendered !== eqBlocks` and the check fails.
- `verify_45`, `verify_46` and `verify_47` all still pass — checked, per the standing rule. The new
  shader pair is why nothing broke this time.
