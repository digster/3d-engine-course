## Seven findings; two fixed, and both were promises already on record

- **`engine.hpp` listed 40 of the 55 headers it could have** — the whole ECS, the asset store,
  handles, pools, the logger, the assertions, the action map. The mechanism matters more than the
  bug: `grep -rl engine/engine.hpp` returns the file itself and **nothing else**, so it has never
  been compiled and nothing could ever fail. Three commits in its history; seven lessons in between
  shipped fourteen headers and touched it zero times. Fixed, then **checked at configure time** by a
  glob used as a lint (proven to fail by deleting one include). The compile measurement came out
  **backwards** — the broken umbrella was *cheaper* (0.28 s) than explicit includes (0.37 s),
  because the omitted fourteen are the templated ones.
- **`scene.hpp` has said since 5.1 that "Module 5's ECS replaces the struct with components"**, and
  Module 5 never did it. Now `gfx/renderable.hpp` + `collect_renderables()`. **Hoisted at two
  callers against the engine's own three-caller rule**, with a narrow reason: what is duplicated is
  not an idiom but a known-broken `mat4`→`transform` conversion whose removal `ecs_swarm` predicted
  for Module 6 — and Module 6 has been written and `scene_object` still holds a `transform`.

Left open, named and dated: `view()` has no `const` overload (the signature is left looking wrong on
purpose); no public entity→GPU path (`sandbox` bridges it privately in ~700 lines, which is why
nobody noticed); no collision; no text; no audio; and a program cannot *name* its own log category.

## Two bugs this session shipped and then caught

- **The boom's composition order.** `L = (H·Rz(β)·S)⁻¹·H = S⁻¹·Rz(−β)` — the inverse of a product
  reverses. Written the way the English reads, the two agree on *x* to four decimals and differ by
  **36%** on *y*. The symptom was not a tilted horizon: `view_from_camera`'s `is_rigid` assertion
  fired, and the **headless `--shot` run hung for ever with no output**, because `SDL_assert` is a
  retry loop and a build server has no dialog to answer it. `sample <pid>` named it in one command.
- **The unit-cube convention, three times in one file.** Cube spans ±0.5 (scale = full size);
  icosahedron has radius 1 (scale = radius). Floor a quarter of its area, boxes half-buried, debug
  OBBs *exactly* 2× too big — which reads as a deliberate collision margin. Answered with `box_at()`.

## Second pass, same day — the 13 silent SVG fills, fixed

Filed as out of scope during 5.12, then picked up. `apply-shared.py --check` was exiting 1 on 13
inline `fill="…"` attributes on SVG `<text>` in 06-02 and 06-03, all silently overridden by
`course.css`. **Now zero, and `apply-shared.py --check` exits 0.**

The useful part was that the colour was doing **two different jobs** and needed two different fixes:

- **06-02 fig 2 — semantic.** Two quantities fall by four and one does not. The verdict row fifteen
  lines below in the same figure already said that with `t-bad` / `t-ok`, so the value labels now
  use the same two classes and the figure's claim reads at a glance instead of by tracing columns.
- **06-03 figs 2, 4, 5 — series identity.** Which curve is this? There is no class for the figure
  palette and there should not be one (those hexes are *not* the axis colours, and minting
  `.t-green` invites somebody to colour an axis with it). The answer was the idiom the same file
  already uses twice for its own legends: **a coloured shape beside plain text** — `fill` works fine
  on `line`/`rect`/`path`, the rule only targets `text`. Three of the four sites already had a grey
  leader dash that only had to stop being grey.

Fixed in `figs_62.py` / `figs_63.py`, **not** in the HTML — the drift recurses (page ← svg ←
generator), and `check-builders.py --figures 62 63` is what proves it landed: 2/2.
