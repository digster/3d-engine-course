## The derivation (five lines, and it covers everything)

An attribute linear over the surface is `a = αx_v + βy_v + γz_v + δ`. Substitute the projection
(`x_v = (aspect/f)·x_n·w`, etc.) and divide by `w`:

    a/w = ( α(aspect/f)x_n + β(1/f)y_n − γ )  +  δ·(1/w)

— affine, plus a constant times an affine thing (3.1 proved `1/w` is affine), hence **affine**. So
interpolate `a/w` and `1/w` and divide. The four constants cancel and are never computed, which is
why one derivation covers uv, colour, normals and anything else.

**Depth is the exception** and the code says so where someone would otherwise "fix" it: device
depth is already affine, so it is interpolated directly.

## Verified, not asserted

- 199,241 random triangles: perspective-correct wrong by ≤ `1.3e-12`; affine by up to **9.89**.
- Worked example (`w` 1→100, screen midpoint): true `u = 0.00990099`; affine `0.5` (**50.5×** off);
  `0.005 / 0.505` = the truth exactly.
- **Depth control:** 20,590 colour pixels change, `0` depth pixels change.
- **2-D control:** 17,275 covered pixels, `0` differences between modes.
- Tessellation: worst uv error `4.23 → 1.83 → 0.76 → 0.29 → 0.10 → 0.03` cells; ratios 2.31, 2.42,
  2.62, 2.84, 3.10 → 4 (second order). Still **381 px wrong at 2,048 triangles**.

## Two things worth remembering

- **The pixel-difference metric saturated** at ~48% for four tessellation levels then fell off a
  cliff — not the error behaving oddly, the *metric* capping. You cannot be more wrong than a coin
  flip about a two-colour pattern. Measuring the raw uv error showed the real convergence.
- **The 64-vertex scratch array** in `collect_triangles` clamped with `std::min` — which would have
  silently drawn a fraction of the 289-vertex floor. A truncating limit turns a capacity bug into a
  rendering bug. Replaced with vectors owned across frames.
